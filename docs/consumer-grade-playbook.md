# 别人怎么做到“消费级”（对标拆解）

样本：README / landing / 公开描述层面的 10 个项目，star 数为 2026-10-25 现读。**不是代码审计，也不是排行榜**；只看它们如何让陌生人第一次用起来。

## 六种做法

### 1. 单场景输入 → 输出（最容易被简历讲清楚）

- **roomGPT**（10,694 stars）：上传一张房间照片 → 生成装修效果图。首屏就是工具，不需要先读文档。
- **restorePhotos**（4,439 stars）：上传旧照片 → 修复。一个输入、一个输出、一个 hosted demo。

共同点：**一句话能说完**；首屏没有导航迷宫；README 第一屏就是 GIF/前后对比；免费试用不需要账号。

### 2. 把安装摩擦压到最低

- **Jan**（45,069 stars）：桌面安装包，离线运行，首次打开就是聊天框。
- **Open WebUI**（156,689 stars）：一条 Docker 命令起服务；文档第一屏是 quick start。
- **AnythingLLM**（67,532 stars）：桌面版 + Docker，本地优先，首屏引导选模型/文档。

共同点：**不要求用户先理解架构**；安装路径不超过两步；默认配置能跑；错误信息指向下一步。

### 3. 寄生在用户已经在用的工具里

- **papersgpt-for-zotero**（2,682 stars）：不要求用户换工具，直接装在 Zotero 里，对 PDF 提问、搜全库。

共同点：**借用宿主的分发和信任**；不需要自己拉新；安装动作就是“装一个插件”。

### 4. 把“隐私/本地”做成可感知的卖点

- **meetily**（32,141 stars）：隐私优先的会议助手，本地转录 + Ollama 总结，明确说数据留在本机。
- **khoj**（37,813 stars）：可自托管的个人 AI 第二大脑，强调“your data”。

共同点：隐私不是一句口号，而是**首屏可见的默认值**（本地、离线、可自托管）；用户能一眼判断“我的数据去哪”。

### 5. 面向一个具体职业/任务的完整工作流

- **ResumeForge**（350 stars）：本地优先的 AI 简历工作台，岗位管理、事实台账防虚构、定制简历。
- **resume-lm**（332 stars）：Next.js 的 AI 简历定制，几分钟产出岗位匹配版本。

共同点：**不是“AI 工具”，而是“求职这件事的流程”**；用户知道什么时候用它、用完得到什么。

### 6. 模板/多端/平台型（最难做出差异）

- **NextChat**（88,892）、**LibreChat**（46,279）：零配置聊天、多模型、一键部署。
- 共同点：分发强、功能全，但**个人开发者很难在这里做出“非它不可”**；更适合学习架构，不适合当第一个消费级作品。

## 共同结构（比功能数量重要）

1. **首屏就是产品**：不是“欢迎来到平台”，而是直接上传/输入/开始。
2. **不需要账号就能看到结果**：demo 数据、示例、游客模式。
3. **一句话说清“帮谁解决什么”**：README 第一行、landing 第一屏一致。
4. **视觉证据**：GIF/视频/前后对比，比功能列表更有说服力。
5. **安装路径短**：桌面安装包、Docker 一行、浏览器插件、PWA 加到主屏。
6. **诚实边界**：本地/云端、能做什么/不做什么、内测状态；不编造用户数和排名。
7. **反馈入口**：issue、反馈按钮、更新日志；用户知道“说了会被看到”。
8. **一个明确的北极星**：roomGPT 是“生成一张图”，meetily 是“一次会议记录”，不是 DAU/功能数。

## 映射到 study-buddy

已经有的：

- 单场景：考研长线陪伴；首屏就是今日建议。
- 免注册：`?demo=1` 直接进示例数据；本地模式昵称即可。
- 安装：PWA 可加到主屏；Android/小程序代码在仓库。
- 隐私：本地优先 + 可选 Supabase；独立隐私页。
- 视觉证据：真实截图、30 秒录屏、OG 分享图。
- 反馈：应用内“反馈”入口 + GitHub Issues。

还缺的（按优先级）：

1. **一个公开 URL**（D1–2）——没有链接，以上都只是仓库。
2. **10 个真实用户 + 3 次观察**（D11–12）——这是“消费级”与“作品集”的分界线。
3. **Android APK / 小程序码**（D9–10）——需要 SDK/AppID；没有就先写“内测中”，不要放假二维码。
4. **一个北极星指标**：建议先用“首次打开 5 分钟内完成第一件任务”的激活率，而不是下载量/star。

## 12 项消费级检查表

- [ ] 一句话说清用户与任务
- [ ] 公开 HTTPS 链接
- [ ] 免注册 demo / 示例数据
- [ ] 3 步内完成首次使用
- [ ] 手机可用（PWA/小程序/APK 至少一种）
- [ ] 首屏有真实截图或 30 秒视频
- [ ] 安装说明一屏
- [ ] 隐私说明与删除方式
- [ ] 反馈入口
- [ ] 一个可复算的激活指标
- [ ] 10 个真实用户、3 次观察、3 个修复
- [ ] 发布帖与简历 bullet 只写已发生的事

## 不要照抄

- **不要为了“像平台”而加多模型、多代理、插件市场**；个人项目先赢一个场景。
- **不要编造用户评价、下载量、排名**；一次被拆穿，整条作品线失去可信度。
- **不要把 star 当北极星**；star 是分发结果，不是产品质量。
- **不要把内测功能写成默认能力**（例如 AI 名师）；边界写清楚反而更容易被信任。

## 一句话总结

消费级不是“功能多”，而是：**陌生人不用读文档，5 分钟内完成一次有价值的事，并且知道下一步在哪。**
