# Paper — 给她 · 考研陪伴 技术说明（设计文档）

> 这是一篇**技术设计说明**（非同行评审论文），如实描述 study-buddy 的真实架构与设计决策。
> 所有结构、参数、数字均取自仓库真实代码（`src/lib/`、`test/`、`docs/user-validation-status.md`）。

## 1. 问题

考研长线（408 统考，四科 150 分）需要：**给方向**（课纲、排期、目标）、**护情绪**（降低焦虑）、
**尊重人**（不监工）。市面上「督学」产品多是监控式（看数据、推送提醒），容易加重焦虑，且不按
11408 课纲排期。

## 2. 架构：双模式数据层 + 11408 课纲周计划

```
┌─ 本地模式（默认，无配置）─────────────┐   ┌─ 云端同步（Supabase）────────────┐
│ src/lib/db.js  localStorage 双模式层  │   │ supabase-all-in-one.sql          │
│   tasks / focus / checkins / goals    │   │  RLS 行级安全（仅同小组两人可见） │
└──────────────────────────────────────┘   └──────────────────────────────────┘
         ▲ 统一数据层接口（db.js 屏蔽模式差异）
src/lib/curriculum.js  —— 11408 课纲 + 四科分值权重 + 按周轮转 buildPlan(anchor, today)
```

| 模块 | 真实职责 | 文件 |
|---|---|---|
| 数据层 | 本地 + Supabase 双模式，统一接口 | `src/lib/db.js` |
| 课纲/计划 | 11408 四科权重 + 开箱即用周计划 | `src/lib/curriculum.js` |
| 题库 | 数学/英语/政治/写作 + 错题本 | `src/lib/qbank*.js` |
| 规划/统计 | 目标、统计、推荐、趋势 | `src/lib/plan*.js` |
| OTA | 自建更新通道 | `src/lib/ota.js` |
| UI | 60+ 组件：Tasks/Pomodoro/Progress/Mood/StudentView/SupervisorView（去监控化） | `src/components/` |

## 3. 关键设计决策

- **双模式数据层**：未配置 Supabase 自动进本地模式，所有功能（除远程看）立即可用——降低上手门槛。
- **11408 课纲权重**：数据结构 45 / 组成 45 / OS 35 / 网络 25 = 150；按周轮转从每科取一个主题，
  自动排「今日建议 3 件事」——零规划负担（消除「不会自己填」的决策负担）。
- **去监控化**：她的数字默认不主动推送，想看才点开；督学端「陪她」而非「看她数据」。
- **情绪优先**：倒计时措辞「紧迫」→「陪伴」且可收起；树洞（私密）、深呼吸 60 秒兜底。
- **决策过滤器**：新功能须至少服务一根支柱且不违背另一根（为提分而加重焦虑的改动一票否决）。

## 5. 边界（证明什么 / 不证明什么）

**证明**：
- 本地模式完整可运行（`?demo=1` 演示路径、今日建议、任务状态流转、390×844 无横向溢出）。
- 单元测试与题库校验通过（11 测试 + 20 项题库不变量）。
- 11408 课纲与四科分值权重可复算（数据结构 45/组成 45/OS 35/网络 25 = 150）。

**不证明**：
- **真实用户验证未开始**（真实用户 0、招募未开始）；`?demo=1` 用合成数据，**不能替代真实用户**。
- 留存、增长、付费或「消费级」已达成；陌生人能无提示完成首次任务、48 小时续用、
  Supabase 多设备稳定、PWA 各 iOS/Android 版本行为一致。
- 云端同步未在真实网络与多设备上验证；Android APK / 微信小程序未构建、未上传（无 SDK/AppID）。
