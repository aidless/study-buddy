# 安全审计报告（2026-08-10）

## 审计范围
Supabase 数据层（RLS 策略）、Edge Function 鉴权、客户端密钥管理。

## 结论
整体设计良好：`my_couple_id()` 使用 SECURITY DEFINER + search_path 锁定；所有业务表按 couple 隔离；错题本按 owner 写权限；存储桶按 couple 目录隔离。发现 2 个问题，均已修复/给出修复方案。

## 发现与处置

| # | 问题 | 风险 | 处置 |
|---|---|---|---|
| 1 | `profiles_update` 只校验 `id = auth.uid()`，未限制可更新列——用户可改自己的 `couple_id` 逃逸小组或读取他人数据 | 高 | ✅ 已修复：with check 增加 `couple_id = my_couple_id()`（见迁移 `supabase/migrations/20260810_rls_hardening.sql`，需在 SQL Editor 执行） |
| 2 | AI 名师 Edge Function `verify_jwt = false`，任何人可调用烧模型额度 | 高 | ✅ 已修复：verify_jwt=true + 客户端携带 anon key（已实测无鉴权 401 / 带鉴权 200） |
| 3 | `couples_insert with check (true)`，任意登录用户可无限建组 | 中 | ⚠️ 暂缓：注册必需；用户量增长后在业务层加限频 |
| 4 | 邮箱确认关闭（enable_confirmations=false），注册无邮件验证 | 中 | ⚠️ 建议上架前开启邮箱确认或短信验证，减少批量注册 |
| 5 | 密码最短 6 位 | 低 | ⚠️ 建议提升至 8 位并加复杂度要求 |

## 建议上架前补充
- 全表 RLS 复检（引入新表必须显式建策略）
- 生产环境开启 MFA 可选、会话过期策略
- 存储桶 ACL 复检：`updates` 桶为公开（OTA 包，必须公开）；`wrong-images` 仅 couple 可读
