# Review-Agent V4 P0 -- Full-Submission Review Path

_2026-08-06_

## Scope

V4 P0 adds the highest-quality, full-submission review path. Instead of
feeding a reviewer the first bounded evidence packet derived from a title and
abstract, the CLI accepts a real submission directory, builds a
provenance-preserving chunk manifest, reviews **every** narrative chunk in
bounded packets, runs read-only artifact checks, and produces one strict
cross-packet Area Chair synthesis plus an auditable bundle.

The path is fail-closed: no offline-stub fallback, no silent chunk drops, no
loose JSON schema acceptance, and no evidence SHA-256 mismatch.

## New modules

| Module | Responsibility |
|---|---|
| `agents/submission.py` | Deterministic UTF-8 intake of `.md`, `.txt`, `.tex`, `.bib`; format-aware structural chunking; SHA-256 per file/chunk; fail-closed coverage gates. |
| `agents/full_submission_review.py` | Packs all narrative chunks into bounded evidence packets, reviews each packet, synthesizes one strict Area Chair review, and verifies full coverage. |
| `agents/artifact_verifier.py` | Read-only static checks for citations, claims.tsv, Python statistics, and preregistration disclosure; never imports or executes submitted code. |
| `agents/claim_ledger.py` | Converts deterministic artifact findings into provenance-checked claims that the Area Chair can consume. |

## CLI contract

```powershell
python -m agents.cli review `
  --quality highest `
  --submission-dir '<submission directory>' `
  --conference tmlr `
  --bundle-dir '<output directory>' `
  --pretty
```

`--quality highest` locks multi-reviewer + revision + MMR + self-consistency 2,
requires a live LLM, and enables strict JSON schema validation at persona,
cross-examination, revision, Area Chair, and evaluation-Judge boundaries.

The bundle contains:

- `manifest.json` -- run manifest with input fingerprints, model, parameters,
  packet list, and result status;
- `review.json` -- packet reviews, final meta review, artifact findings, and
  claim ledger;
- `submission_manifest.json` / `chunk_manifest.json` -- per-file and per-chunk
  SHA-256 provenance;
- `artifact_findings.json` -- deterministic static-analysis report.

## Fail-closed guarantees

- Every narrative chunk appears in exactly one packet; the invariant is
  checked before and after review.
- A packet cannot be created whose body plus mandatory header exceeds the
  caller's character cap.  A header budget is reserved while packing.
- Highest-quality runs fail if the LLM is unavailable, if a persona or AC
  payload violates the strict schema, if a packet review uses an offline
  fallback, or if evidence-packet SHA-256 does not match the manifest.
- Artifact intake fails closed on unreadable input, invalid UTF-8, or
  high/critical input-severity findings.

## Verification (2026-08-06)

- Full offline suite: **153 passed** (Python 3.12.13, ~9 minutes), covering
  legacy v1/v2/v3 behavior, TMLR quality eval, training smoke, and the new V4
  modules.
- Real-directory smoke (AGI Kit `papers` root snapshot, 6 supported files):
  81 chunks, 81 narrative chunks, 8 packets, coverage pass, submission
  SHA-256 recorded in `outputs/v4_p0_smoke_20260806/smoke_report.json`.
- Edge-case smoke (full AGI Kit `papers` tree, 25 supported files): 469
  chunks, 107 packets, max packet 15,581 chars, coverage pass.  This input
  exposed and validated the header-budget fix.

## Known limits (later V4 work)

- PDF/OCR, LaTeX include expansion, table/figure extraction, DOI validation,
  and sandboxed statistical recomputation are not implemented yet.
- The artifact verifier is intentionally conservative: findings are
  candidates with exact locators and `requires_manual_verification` flags,
  never automatic accusations.
