# 自进化 Agent 实验框架：三个可选方案

日期：2026-08-06

## 共用约束（三个方案都必须遵守）

- 硬件：16GB RAM / RTX 3060 Laptop 6GB，消费级，串行运行，跑完 `ollama stop`；
- 现有 20 题只作为 `legacy_regression`，不承载迁移、泛化、累积改善或递归主张；
- 控制面（任务清单、验证器、晋升门、权限 broker、账本、回滚路径）冻结且不可由候选修改；
- 验证证据分型：`bug_discriminating` / `regression_only` / `unprovable`，晋升须同时满足目标行为 oracle 与非回归 oracle；
- 预算向量 B = (模型/摘要、提示模板哈希、输入/输出 token、调用数、重试数、工具调用数、墙钟时间)，任何臂间比较都预算匹配；
- 任何进入 validation / sealed_final 的任务、轨迹或错误不得回流为技能、提示或训练文本；
- 负结果是正常结果，照常报告。

---

## 方案 A：模型与外壳对照线（最省，立即执行）

**一句话**：先把开放问题关掉——换模型、换外壳到底改不改变 20 题通过率。

**回答的问题**：H1（模型选择差异）与 H3（外壳的复合系统效应）。

**实验设计**（即现有 Phase 1–2，加上可选 H3）：

1. 复测 qwen2.5-coder:7b：最小生成探针 → smoke 10 → full 20（需先修接口无输出问题）；
2. 拉取 hermes3:8b（决策点 D1，约 4.9GB）→ 最小探针 → smoke 10 → full 20；
3. qwen3:1.7b 升 full 20（决策点 D2）；
4. H3 外壳对照（决策点 D3）：同一模型、同一 20 题，分别在本机 Harness 与 Hermes Agent 外壳中运行，输入/输出 token、调用数、重试数和墙钟时间预算匹配；结果只报复合系统效应；
5. McNemar 配对比较 + 类别分解（exception/boundary/state/tool_error）+ 语法有效率 + 耗时；
6. 产出 `SELFEVOLVE_REPORT_V2.md`。

**臂**：no_change / heuristic / qwen2.5:7b full / qwen2.5-coder:7b full / qwen3:1.7b full / hermes3:8b full（外壳对照臂可选）。

**资源**：约 4.9GB 下载 + 每个 full 20 模型一次推理窗口；分批执行，风险低。

**决策门**：D1、D2、D3。

**交付**：每个模型两个证据 JSON + 汇总统计表 + 统计比较报告。

**失败定义**：模型间无显著差异、外壳无差异或 qwen2.5-coder 接口不可修复——均为负结果，直接记录。

**优点**：成本最低、不依赖新任务建设、立刻可跑。

**缺点**：完全不检验自进化，只是评测；不能支撑任何"学习/进化"结论。

---

## 方案 C：最小可信闭环（先造"门"，再谈"进化"；工程与研究并重）

**一句话**：先做一个会被坏候选攻击、且真的会拒绝坏候选的最小闭环，再在其上跑一个小规模 A/B。

**回答的问题**：控制面与升级门是否可证伪地有效？一个最小的技能更新机制能否带来预算匹配的净改善？

**实验设计**：

1. 实现可信控制面：specification、validators、sealed evaluator、permission broker、promotion controller、append-only log、rollback controller；
2. 候选状态机：`stable -> proposed -> admitted -> sealed_evaluated -> promoted | rejected`，异常/超时/预算超限一律走 rejected 或原子 rollback；
3. 破环测试（adversarial tests）：注入已知坏候选——放宽测试、删负样本、改账本、绕过权限、突破预算——确认全部被拒绝且可回滚；任一坏候选被放行即控制面不合格，必须先修复再继续；
4. 新建小型任务流（规则族隔离，不随机单题切分）：例如 3 个规则族 × 10 题 = 30 题，按 15 / 5 / 10 分 acquisition / validation / sealed_final；任务登记 split、来源、创建/冻结时间、暴露状态与内容哈希；
5. 跑三臂：base / base+token-matched placebo / base+curated skills（skills 只来自 acquisition）；
6. 每臂记录预算向量；晋升用 `delta_min` + 双 oracle + `best_so_far` 回滚；sealed_final 只在报告时运行一次；
7. 报告 delta 与置信区间，不挑 p 值。

**资源**：主要是实现工程量（控制面 + 测试），推理预算小（3 臂 × 30 题规模）。

**决策门**：需要批准建立新任务流（D5 的最小版本）。

**交付**：控制面代码与破环测试、任务流与暴露账本、三臂证据、一份诚实报告（正或负）。

**失败定义**：坏候选被放行 → 控制面不合格，必须修；技能臂无净收益 → 负结果，但门本身仍然有效，负结果照常发表。

**优点**：闭环最短、机制可审计、与最新文献（可证伪发布门、验证证据分型、EA-Graph）直接对齐；后续可平滑扩展成方案 B。

**缺点**：30 题统计功效弱，正向结论只能限定为"在这组任务上存在差异"，不能撑起强泛化主张。

## 方案 B：完整受限自进化研究线（最强证据，最高成本）

**一句话**：在规则族隔离的三层任务流上，逐组件检验"结构化经验/技能是否带来预算匹配的净改善"。

**回答的问题**：H2（上下文增强的条件效应）+ 生命周期适配 + 技能迁移是否成立。

**实验设计**（现有 Phase 3 的完整版）：

1. 构建更大任务库：例如 4 个规则族 × 12 题 = 48 题，按 24 / 12 / 12 分 acquisition / validation / sealed_final；规则族隔离，避免同一程序模式泄漏到部署集；
2. 冻结任务注册、暴露账本、评测器与勘误链；隐藏验证器审计"任务说明—oracle—测试充分性"；
3. 五臂对照：no-skill / raw-trajectory / token-matched placebo / structured reflection / reflection + curated skills；另加持久状态关闭对照；
4. Curator 作为独立可消融控制器：retain(skill) 规则 = support ≥ m 且 marginal_value ≥ η 且 contradiction_rate ≤ ρ；技能评测拆分为 Trigger / Compliance / Boundary 三指标；
5. 并行或多源经验更新时，组合体必须作为独立候选做 scope/兼容性审计与独立 validation，不得直接合并；
6. 每轮由独立 validation 选 `best_so_far`，禁止默认"最后一轮最佳"；此前已通过任务持续作为回归义务；证据漂移降为 `unprovable` 后必须重验；
7. 反思与检索误导鲁棒性测试（负例记忆、过时经验、误导召回）；
8. 若资源允许再进 Phase 4（LoRA 训练闭环，仅用 acquisition 数据），与 Phase 3 严格区分、不并行。

**资源**：任务构建为主要成本（需要人工撰写 + 审计）；推理预算中等偏上（多臂 × 多轮）；需要多个空闲窗口，不与 P1 训练/TMLR 评审并行。

**决策门**：D5 完整批准 + 任务流与控制面冻结 + 资源窗口。

**交付**：任务库、暴露账本、逐组件证据与报告；任何组件未提升则停止该组件并写负结果；只有当改善机制自身在后续锁定周期中边际改善更大时，才允许使用"递归自我改进"术语。

**失败定义**：技能无迁移、反思无净收益、组合更新不安全——全部是重要发现，照常报告。

**优点**：唯一能支撑"受限自进化"较强主张的路线；与 SkillEvolBench、Argus、EvolveNet 等最新工作直接可比。

**缺点**：成本最高、周期最长、空结果风险大（最新文献倾向认为当前 Agent 的技能迁移很弱）。

## 三者对比

| 维度 | 方案 A 模型/外壳对照 | 方案 C 最小可信闭环 | 方案 B 完整研究线 |
| --- | --- | --- | --- |
| 回答的问题 | H1 + H3 | 门是否有效 + 最小技能机制 | H2 + 生命周期适配 + 迁移 |
| 证据上限 | legacy regression 描述 | 小规模净差异 + 机制审计 | 三层隔离下的净改善 |
| 立即可行性 | 高（等资源窗口即可） | 中（需先实现控制面） | 低（需先建任务库） |
| 工作量/成本 | 低 | 中 | 高 |
| 主要风险 | 只是评测，无进化结论 | 统计功效弱 | 任务建设成本 + 空结果 |
| 可发表性 | 较低（纯基线报告） | 中（机制/门本身可写） | 最高 |
| 后续衔接 | 为 B/C 提供模型基线 | 可直接扩展成 B | 终点 |

## 建议路线

先执行 A（把模型与外壳开放问题关掉，成本最低、不阻塞），同时若用户批准新任务流，就做 C（最小闭环，先证明门有效），C 的控制面与任务流直接复用于 B。若目标就是一篇完整论文且愿意承担最高成本，可直接选 B；若只想先把地基打扎实，选 A → C。

三个方案互斥性说明：A 与 C/B 不冲突，可串行衔接；C 与 B 是规模与深度的两级，不建议同时并行（资源不允许）。
