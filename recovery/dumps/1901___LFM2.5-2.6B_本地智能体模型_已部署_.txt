# LFM2.5-2.6B 本地智能体模型（已部署）

## 模型

- 名称：Liquid AI LFM2.5-2.6B（2026-08-04 发布，端侧智能体模型）
- 量化：Q4_K_M（GGUF，约 1.6 GB）
- 许可证：LFM Open License v1.0（见本目录 `license.bin`，基于 Apache 2.0，可商用；年收入超过 1000 万美元才涉及付费）
- 来源：HuggingFace 直连在本网络不可用，通过 Ollama 社区镜像 `oamazonasgabriel/lfm2.5-2.6b:q4_k_m-8gbGPU` 获取；模型 blob SHA-256 已校验与镜像一致

## 智能体接入方式（推荐）

模型由 **llama.cpp 的 llama-server** 提供服务，OpenAI 兼容端点：

- Base URL：`http://127.0.0.1:8080/v1`
- 模型名：`lfm2.5-2.6b`
- API Key：不校验，填任意值或不填
- 能力：`/v1/chat/completions`、流式输出、原生工具调用（`tool_calls`）、`reasoning_content`（思考过程）

实测工具调用闭环正常：

1. 用户请求 → 返回 `finish_reason=tool_calls`，如 `get_weather({"location":"Paris"})`
2. 提交工具结果（role=tool）→ 模型给出最终回答

本机性能：GPU 卸载下约 **70 tok/s**；纯 CPU 约 10 tok/s。

## 启动 / 停止

启动（已配置 16K 上下文、GPU 卸载、Jinja 模板）：

```powershell
powershell -ExecutionPolicy Bypass -File "C:\Users\Administrator\AppData\Roaming\haolo_desktop\thread-groups\default\科研\outputs\lfm2.5-2.6b\start-lfm2.5-agent.ps1"
```

停止：

```powershell
Get-CimInstance Win32_Process -Filter "Name='llama-server.exe'" | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

服务端日志：`outputs\lfm2.5-2.6b\llama-server.log`（该目录内）。

## 为什么不用 Ollama 跑智能体

模型同时已导入 Ollama（`lfm2.5:2.6b`，普通对话可用）。但 Ollama 0.24 无法解析该模型的**原生工具调用格式**——LFM2.5 输出的是
`<|tool_call_start|>[get_weather(location='Paris')]<|tool_call_end|>`，Ollama 只认标记内的 JSON 数组格式，所以 `/api/chat` 带
tools 时不会返回 `tool_calls`。llama.cpp 完整实现了 GGUF 内嵌的 Jinja 模板，能正确解析并返回结构化工具调用，因此智能体统一走
`http://127.0.0.1:8080/v1`。

## 备注

- 当前机器显存常被其他任务占用；如遇 CUDA 显存不足，可把启动脚本中 `--n-gpu-layers 99` 调低（如 22），或改为 `0` 纯 CPU 跑。
- 上下文默认 16K（硬件限制）；模型原生支持 128K，需要长上下文时可把脚本里 `-c 16384` 调大，但会占用更多内存/显存。
